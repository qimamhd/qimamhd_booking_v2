# UI/UX Principles

1. The booking form is a workspace, not a database dump.
2. First viewport: customer, date, hall, periods, guest count, package, state and financial summary.
3. Secondary data lives in tabs, smart buttons or focused popups.
4. Quick Booking is a popup for the common fast path.
5. Cancellation is a popup because it requires reason + financial safety checks.
6. Payment/invoice configuration belongs in Settings, not every booking.
7. Availability should be visual: halls × periods for one selected day.
8. Warnings appear only when actionable.
9. Avoid excessive colors; use state color as a signal, not decoration.
10. Arabic RTL is a first-class layout target.
11. Smart suggestions must state why they are suggested.
12. Do not show accounting internals to reception users unless needed.
